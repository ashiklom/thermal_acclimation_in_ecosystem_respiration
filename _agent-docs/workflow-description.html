Workflow Description

Thermal Acclimation in Ecosystem Respiration — Steps 01–04

This pipeline estimates how ecosystem respiration (ER) acclimates to temperature changes and projects future ER under climate warming. It processes eddy covariance data from AmeriFlux, ICOS, and TERN through four sequential stages: data preparation, thermal acclimation estimation, driver identification, and future prediction.

High-Level Flow

Step 01: Data Preparation |-- 01_01: Estimate missing soil temperatures via Random Forest |-- 01_02b: Quality-control nighttime NEE (AmeriFlux sources) |-- 01_02c: Quality-control nighttime NEE (ICOS sources) '-- 01_02d: Quality-control nighttime NEE (TERN sources) | v Step 02: Thermal Acclimation Estimation |-- 02_01a: Fit temperature-respiration curves (14-day windows) |-- 02_01b: Fit temperature+water+GPP respiration curves (14-day windows) |-- 02_02: Decompose acclimation into direct vs. indirect components '-- 02_03: Validate decomposition via simulation | v Step 03: Driver Identification |-- 03_01: Assemble climate, soil, and spectral predictors '-- 03_02: Random Forest to identify drivers of acclimation | v Step 04: Future Projections |-- 04_01: Estimate future nighttime temperature change (SSP2-4.5) '-- 04_02: Project future ER with and without acclimation effects

Data Sources & the Three-Pipeline Architecture

The pipeline processes eddy covariance data from three flux tower networks: AmeriFlux, ICOS, and TERN. Each source provides data in different formats, with different column naming conventions and quality control standards. The scripts handle these differences through source-specific processing pipelines. Site metadata is stored in data-core/site_info.csv.

FLUXNET-Only Sites (19 sites not yet downloaded)

19 sites in site_info.csv belong to regional flux networks (Swiss FluxNet, CarboEuropeIP, CzechGlobe, etc.) that contribute to FLUXNET synthesis but are not ICOS Ecosystem Tower sites. These sites are listed with source values like FLUXNET2025 or FLUXNET2015 and do not have data in data-raw/ICOS/ or data-raw/TERN/. They must be downloaded via the FLUXNET Shuttle (92-download-fluxnet.sh) and are not processed by the current 01_02b/01_02c/01_02d pipelines.

Sites: CH-Lae, CH-Aws, CH-Fru, CZ-RAJ, CZ-Stn, DE-Gri, DE-Hai, DE-Obe, DE-Akm, DE-Hte, DE-RuC, DE-SfS, ES-LJu, FI-Sod, FR-Pue, IL-Yat, IT-SRo, RU-Fyo, ZA-Kru.

Source Dispatch Mechanism

01_01 dispatches to the correct input file list based on the source field in site_info.csv and the presence of normalized ICOS or TERN files. The source-specific 01_02b, 01_02c, and 01_02d scripts each handle one source exclusively and do not share dispatch logic.

if (site_info$source[id] == "AmeriFlux_BASE") {

} else if (name_site %in% icos_sites) {
  # ICOS: read normalized file from data-raw/ICOS/
} else if (name_site %in% tern_sites) {
  # TERN: read normalized file from data-raw/TERN/
}

For AmeriFlux sites, the scripts check source %in% c("AmeriFlux_BASE", "AmeriFlux_FLUXNET") and branch into a separate code path.

Three Source-Specific Pipelines

Key architectural detail: the original pipeline used 01_02a (EuroFlux/ICOS) and 01_02b (AmeriFlux) as two source-specific pipelines. After the data-directory reorganization, 01_02a was deleted and replaced by 01_02c (ICOS-only) and 01_02d (TERN-only). The current Step 01 has three independent source-specific pipelines, each producing the same output schema.
Script Source Key Characteristics
01_02b AmeriFlux_BASE Site-specific column names via site_info config; computes nighttime via suncalc; performs REddyProc u* threshold estimation and NEE gap-filling; extensive site-specific sensor corrections
01_02c ICOS (normalized L2) Standardized column names from 93-download-icos.py; QC flags from dataset; NIGHT column provided; no u* filtering needed (pre-processed)
01_02d TERN (normalized L3) Standardized column names from 94-download-tern.py; similar to ICOS pipeline; uses measured TERN soil temperature directly

Historical note: the original 01_02a script handled FLUXNET2015/2020/2025 and ICOS2025 sources via compound source dispatch, concatenating data from multiple FLUXNET-era file layouts. It was deleted once the ICOS-only (01_02c) and TERN-only (01_02d) pipelines were implemented and the legacy FLUXNET file layouts were no longer referenced by active workflows. The multi-source concatenation logic (joining FLUXNET2025 and ICOS2025 periods for compound-source sites) is no longer needed because each pipeline now handles a single normalized data product.

Steps 02–04 are source-agnostic: they read the standardized output files (_nightNEE.csv, _ac.csv) and never reference data source identifiers.

Column Name Conventions by Source

ICOS and TERN sources use a standardized naming scheme with suffixes that encode processing method and quality:

Column Meaning Source
TA_F_MDS Air temperature, gap-filled by marginal distribution sampling ICOS/TERN
TS_F_MDS_1 / TS_F_MDS_2 Soil temperature at layer 1/2, gap-filled ICOS/TERN
NEE_VUT_REF Net ecosystem exchange, VUT method with reference u* ICOS/TERN
NEE_VUT_REF_QC Quality flag for NEE (0=measured, 1–2=good gap-fill, 3=poor) ICOS/TERN
SWC_F_MDS_1 Soil water content, gap-filled ICOS/TERN
GPP_DT_VUT_REF Gross primary production, daytime VUT method ICOS/TERN
NIGHT Nighttime indicator (1=night, 0=day), computed from solar geometry ICOS/TERN
TIMESTAMP_START Measurement start time (YYYYMMDDHHMM) ICOS/TERN

AmeriFlux sites use site-specific variable names configured in site_info.csv. For example, soil temperature might be TS_PI_F_1_1_1, TS_1_1_1, TS_PI_1, or TS_2_1_1 depending on the site and sensor depth. Air temperature might be TA_PI_F_1_1_1, TA_1_1_1, T_SONIC, or T_SONIC_1_1_1. NEE is constructed by summing component fluxes, e.g., FC + SC_PI_F or FC_1_1_1 + SC_1_1_1. These mappings are read dynamically: 

# AmeriFlux column dispatch (01_02b)
NEEvars <- trimws(unlist(strsplit(site_info$NEE[id], "\\+")))
ac$TA <- a[, trimws(site_info$TA[id])]
ac$TS <- a[, trimws(site_info$TS[id])]

Site-Specific Corrections

Each pipeline applies per-site corrections for sensor issues, missing data, and site-specific quirks. These are hard-coded conditionals within the scripts.

ICOS corrections (01_02c):

  • FR-FBn: Reads predicted TS from Random Forest output generated by 01_01 when configured with estimate_Ts=YES
  • FR-Fon, CH-Dav, FR-Bil: Also reads predicted TS from 01_01 where configured

Historical note: the legacy 01_02a (EuroFlux) script contained extensive site-specific corrections for CZ-Stn, FI-Sod, GF-Guy, FR-Pue, CH-Dav, ZA-Kru, and others. Most of these sites had FLUXNET-era source configurations that are no longer active. The current 01_02c (ICOS-only) pipeline is simpler because it consumes normalized ICOS L2 files and applies fewer site-specific overrides.

TERN corrections (01_02d):

  • AU-Tum: Retains measured TERN soil temperature directly; no RF prediction or site-specific correction needed

AmeriFlux corrections (01_02b):

  • US-Myb: Discards first year; combines TS from two depths using regression
  • US-CMW, CA-Mer: Truncates to data after 2000/1999 respectively
  • US-Jo2: Replaces TA with sonic temperature for a bad period using linear regression
  • US-BZS: Replaces TA for 2012–2014 using nearby US-BZF site data via regression
  • US-Ha2: Combines data from two measurement locations (FC_1_1_1 + FC_2_1_1)
  • US-NR1, US-ICh, US-ICs: Uses PI gap-filled TS data
  • US-Cwt: No TS sensor; estimates from TA using relationship from nearby US-xGB
  • US-MBP: Estimates missing TS from TA via linear regression
  • US-BZo: Uses recent data (>2021) for TS~TA regression calibration
  • CA-ARB, CA-ARF, CA-KLP, US-Rms, US-SRS, US-ChR: Cold-area sites; uses TA > 0 for growing-season TS~TA regression
  • US-KM4: Uses PI gap-filled SW_IN data
  • CA-Man: Combines NEE from FC + SC when NEE is incomplete
  • US-ICt, US-ICh, US-ICs (Arctic): Special daytime handling for midnight-sun periods

Soil Temperature Estimation (01_01) — Source-Specific Model Choice

Script 01_01 uses different modeling strategies depending on data availability, which varies by source:

Model Sites Why
Random Forest with NETRAD DE-Akm, FR-Pue, US-Los, US-SRG, CA-Man, US-Ced, US-Ho1, CZ-RAJ Net radiation available as additional predictor
Linear regression with NETRAD DE-Hte, FR-FBn Limited data prevents RF training
Linear regression without NETRAD GF-Guy and remaining sites No net radiation sensor; uses TA as TS proxy

NETRAD column name also varies by AmeriFlux site: NETRAD_1_1_1 (US-Los, US-Ced), NETRAD (US-SRG, CA-Man), or NETRAD_2_1_1 (US-Ho1).

Step 01: Data Preparation

01_01 — Estimate Missing Soil Temperatures

Runtime: ~5 minutes

Input: Tower data (TA, TS, and NETRAD where available) from AmeriFlux, ICOS, and TERN sources

Output: one file per processed site under data-proc/soil-temperature/{source}/{site}/{site}_TS_rfp.csv

For sites where soil temperature (TS) measurements have gaps, this script trains a Random Forest model (randomForest, 500 trees) on paired TA–TS observations to predict missing TS values. It uses TA and, where configured, NETRAD as predictors, with at most 60,000 training samples. Results are validated against held-out data (R² reported per site).

For TERN and ICOS sites with measured soil temperature, the script retains the measured values directly rather than training a prediction model. Site-specific NETRAD column mapping is handled inline (see table above). The output is consumed by 01_02b (AmeriFlux) and 01_02c (ICOS) for sites that need RF-predicted TS.

01_02b — Quality-Control Nightly NEE (AmeriFlux)

Runtime: ~30 minutes

Input: AmeriFlux BASE data, site metadata, and per-site TS predictions where configured

Output: data-proc/respiration/AmeriFlux/{site}/{site}_ac.csv and {site}_nightNEE.csv per site, plus data-proc/features/growing_season_feature_AmeriFlux.csv

Processes only AmeriFlux_BASE sources. Uses site-specific column names from site_info.csv and performs additional pre-processing not needed for ICOS or TERN.

  • Reads data via amerifluxr::amf_read_base() (handles ZIP extraction and timestamp parsing)
  • Constructs NEE by summing component fluxes (e.g., FC + SC_PI_F)
  • Computes nighttime from sunrise/sunset via suncalc (no NIGHT column provided)
  • Performs u* threshold estimation via REddyProc (ICOS/TERN products already include this)
  • Applies extensive site-specific sensor corrections (US-Myb, US-Jo2, US-BZS, US-Ha2, US-Cwt, etc.)
  • Handles Arctic midnight-sun periods for US-ICt, US-ICh, US-ICs
  • Retains SWC, GPP, and ERA5 soil moisture for the temperature+water+GPP model variant

01_02c — Quality-Control Nightly NEE (ICOS)

Runtime: ~5 minutes

Input: Normalized ICOS L2 files from 93-download-icos.py, site metadata, and RF-predicted TS from 01_01 where configured

Output: data-proc/respiration/ICOS/{site}/{site}_ac.csv and {site}_nightNEE.csv per site, plus data-proc/features/growing_season_feature_ICOS.csv

Historical note: this script replaced the ICOS portion of the legacy 01_02a (EuroFlux) workflow, which handled FLUXNET2015/2020/2025 and ICOS2025 sources via compound source dispatch. The current script consumes only normalized ICOS L2 files and does not read FLUXNET-era file layouts.

Quality control pipeline:

  • Reads TS_F_MDS_1, TA_F_MDS, NEE_VUT_REF directly from normalized ICOS files
  • Filters by TS_F_MDS_1_QC %in% c(0, 1, 2) (excludes poor gap-fills)
  • Filters by NEE_VUT_REF_QC == 0 (measured, not gap-filled)
  • Uses the provided NIGHT column (no solar geometry computation needed)
  • Growing-season identification (handles southern-hemisphere date conventions)
  • Gap detection: removes years with >14-day continuous gaps in growing season
  • Gap-fills TA and TS via hourly/climatological means
  • Removes flagged years specified in site metadata
  • Replaces -9999 sentinel values with NA

01_02d — Quality-Control Nightly NEE (TERN)

Runtime: ~5 minutes

Input: Normalized TERN L3 files from 94-download-tern.py, site metadata

Output: data-proc/respiration/TERN/{site}/{site}_ac.csv and {site}_nightNEE.csv per site, plus data-proc/features/growing_season_feature_TERN.csv

Processes only TERN sources. Similar to the ICOS pipeline but uses TERN-normalized files. TERN provides measured soil temperature directly, so no RF prediction is needed.

Step 02: Thermal Acclimation Estimation

02_01a — Fit Temperature-Respiration Curves

Runtime: ~2 days (Bayesian MCMC per site×window×year)

Input: QC'd nighttime NEE from 01_02b, 01_02c, and 01_02d, site metadata

Output: data/outcome_temp.csv, data/outcome_siteyear_temp.csv

Fits a quadratic temperature-response model to ER in 14-day moving windows across all available years: 

NEE ~ exp(alpha * TS + beta * TS^2) * C0

Uses Bayesian regression via brms (Stan backend) with informative priors. Selects the 3 "control" years closest to the median growing-season soil temperature. For each site×window×year, extracts posterior means of α, β, and C&sub0;.

Computes TAS (Thermal Acclimation Strength) as the window-to-window change in the temperature-response curve midpoint. Also computes day/night temperature sensitivity metrics.

Handles edge cases: extends the fitting window (up to +24 days) if too few observations (<25), removes windows with predominantly negative NEE (i.e., not ER-dominated).

Source handling: This step is fully source-agnostic. It reads the standardized _nightNEE.csv files produced by 01_02b, 01_02c, and 01_02d, which have identical column names regardless of original data source. Growing-season features are loaded via load_growing_season_features(), which combines the three source-specific feature CSVs.

02_01b — Fit Temperature+Water+GPP Respiration Curves

Runtime: ~2 days

Input: QC'd nighttime NEE from 01_02b, site metadata, ERA5 soil moisture

Output: data/outcome_temp_water_gpp.csv, data/outcome_siteyear_temp_water_gpp.csv

Extends 02_01a by adding soil water content (SWC) and GPP as covariates in the ER model. This allows decomposition of thermal acclimation into temperature-driven and water/GPP-mediated components.

02_02 — Decompose Acclimation Components

Runtime: ~1 minute

Input: Outputs from 02_01a and 02_01b

Output: data/acclimation_data.csv

Decomposes total acclimation (TAS_tot) into:

  • TAS (direct): thermal acclimation from the temperature-only model
  • TAS_app (apparent): TAS_tot - TAS, representing the indirect effect mediated by water/GPP

Aggregates per-window results into per-site annual metrics including: mean growing-season temperature, elevation, soil organic carbon, LAI, warming rate, and climate classification.

02_03 — Validate Decomposition via Simulation

Runtime: ~5 minutes

Input: Decomposition results from 02_02

Output: Validation metrics and diagnostic plots

Tests whether the decomposition method correctly recovers known acclimation signals using simulated data with prescribed direct and indirect effects. Confirms the method can distinguish temperature-driven from water-mediated acclimation.

Step 03: Driver Identification

03_01 — Assemble Predictors

Runtime: ~10 minutes

Input: Site metadata, WorldClim climate data, soil data, MODIS LAI

Output: data/predictor_data.csv

Compiles environmental predictors for each site: elevation, mean annual air temperature (MATA), soil organic carbon (SOC), leaf area index (LAI), and historical warming rate. Also computes climate classification (Köppen) and IGBP land cover type.

03_02 — Random Forest Driver Analysis

Runtime: ~10 minutes

Input: Acclimation data from 02_02, predictor data from 03_01

Output: data/partial_plot.csv, data/varImp_plot.csv

Uses Random Forest (randomForest) with 5-fold cross-validation to identify which environmental factors drive variation in:

  • Direct TAS: Elevation and LAI are dominant drivers
  • Total TAS: LAI, elevation, MATA, and SOC all contribute
  • Apparent TAS: MATA, SOC, and LAI dominate (opposite pattern from direct TAS)

Generates bootstrap confidence intervals (200 resamples) for partial dependence plots, stratified by climate–vegetation class.

Step 04: Future Projections

04_01 — Estimate Future Nighttime Temperature Change

Runtime: ~30 minutes

Input: WorldClim v2.1 monthly minimum temperature (baseline 2000–2020; future 2041–2060, SSP2-4.5, 13 GCMs)

Output: data/Tmin_month_ssp245.csv

Computes the difference in monthly nighttime air temperature between the historical baseline and the SSP2-4.5 mid-century ensemble mean. Extracts changes at each FLUXNET site using a 5-cell spatial neighborhood.

04_02 — Project Future Ecosystem Respiration

Runtime: ~7 hours (Bayesian MCMC per site×window)

Input: Growing-season features (01), acclimation data (03), future temperature changes (04_01)

Output: data/acclimation_data_future_ssp245.csv

For each site, fits the ER temperature-response model to control-year data, then projects:

  1. Present ER: baseline nighttime respiration from the fitted model
  2. Future ER (no acclimation): applies the TS change directly to the temperature-response curve
  3. Future ER (with acclimation): modifies the response using the estimated acclimation strength: 
    ER_future_acclimated = ER_present * exp(TAS_tot * DeltaT_growing_season)

The difference between scenarios (2) and (3) quantifies how much thermal acclimation buffers or amplifies the warming-driven increase in ecosystem respiration.

Dependencies

All scripts are written in R and use the following key packages:

  • amerifluxr — reading AmeriFlux BASE data (01_02b)
  • randomForest — soil temperature estimation (01_01) and driver analysis (03_02)
  • brms / rstan — Bayesian regression for ER model fitting (02_01a/b, 04_02)
  • REddyProc — u* threshold estimation and NEE gap-filling for AmeriFlux (01_02b)
  • suncalc — solar geometry for nighttime detection (01_02b)
  • terra — raster operations for climate projections (04_01)
  • tidyverse — data manipulation throughout
  • librarian — non-standard package loading (auto-installs missing packages)
  • ncdf4 — NetCDF reading for WorldClim and ERA5 data
