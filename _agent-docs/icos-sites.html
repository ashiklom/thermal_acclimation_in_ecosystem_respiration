Issues Identified

Issue 1: amerifluxr::amf_download_fluxnet does not work for these sites

The R function amf_download_fluxnet() rejects all FLUXNET estimate_Ts site IDs with "No valid Site ID" errors. The function calls amf_check_site_id() which returns FALSE for FR-Pue, CZ-RAJ, DE-Akm, DE-Hte, FR-FBn, FR-Fon, FR-Bil, CH-Dav. This appears to be a limitation of the API — these sites may not be registered in the AmeriFlux FLUXNET product catalog despite being available through ICOS/EUF.

Workaround: Use fluxnet-shuttle CLI (Python) instead, which downloads from ICOS/EUF data hubs directly.

Issue 2: FR-FBn has no soil temperature data in FLUXNET harmonized format

This is the critical blocker. All other FLUXNET sites have TS_F_MDS_1 columns in their FLUXMET_HH files, but FR-FBn has zero TS_* columns. This is exactly why estimate_Ts=YES for this site — TS must be estimated from TA and NETRAD. But the pipeline needs some measured TS to train the estimation model.

Issue 3: FLUXNET2025_ICOS2025 source requires data from two directories

The 01_01 script splits source on _ and reads from two separate directories in sequence:

  1. FLUXNET2025 → data-raw/SiteData/FLUXNET07202025/unzip/*.csv
  2. ICOS2025 → data-raw/SiteData/Ecosystem final quality (L2) product in ETC-Archive format - release 2025-1/unzip/*.csv

It then bind_rows() the two, splicing on timestamp continuity. For sites like CH-Dav and FR-Bil that already have TS in the FLUXNET file, the ICOS2025 directory is redundant (and currently empty — causing a read.csv("") error). For FR-FBn, the ICOS2025 file was supposed to supply the measured TS that the FLUXNET file lacks.

Issue 4: ICOS native L2 format uses different column names

The ICOS ETC-Archive (native L2) uses sensor-level naming (TS_1_1_1, TA_1_1_1, RA_1_1_1) while the pipeline expects FLUXNET-harmonized names (TS_F_MDS_1, TA_F_MDS, NETRAD). The original author likely had pre-processed ICOS data with FLUXNET-compatible column names.

Suggestions for Next Steps

Option A: Fix FR-FBn specifically (recommended)

The simplest path for the 4 sites with FLUXNET2025_ICOS2025 source:

  1. For FR-Fon, CH-Dav, FR-Bil: change source in site_info.csv from FLUXNET2025_ICOS2025 to just FLUXNET2025. Their FLUXMET_HH files already contain all needed columns.
  2. For FR-FBn: either skip the site, or find another data source for measured soil temperature (e.g., ICOS data portal, author's original data, or manual download of the ICOS L2 product with appropriate column renaming).

Option B: Download ICOS L2 and adapt the script

Download the ICOS ETC-Archive L2 product for FR-FBn, inspect its column names, and either:

  • Add a mapping step that renames ICOS columns to FLUXNET names before bind_rows()
  • Or add a separate ICOS reader path in the script with site-specific column mappings in site_info.csv (similar to how AmeriFlux sites specify TS_1_1_1, TA_PI_F_1_1_1 etc.)

Option C: Create a synthetic TS for FR-FBn

Use the relationship between TA and TS from nearby sites (e.g., FR-Fon) to generate a plausible TS time series for FR-FBn. This is scientifically questionable but would allow the pipeline to run.

Option D: Skip FR-FBn

It's one site out of 16. Remove it from id_estimate_TS or filter it out. The analysis would still have 15 sites.
