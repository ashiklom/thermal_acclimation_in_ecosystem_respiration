Data Directory Cleanup

This document records the data organization and the implemented revision.

Constraints

  • data-raw is only for raw input data downloaded by the download scripts.
  • data-proc is for workflow-generated and otherwise processed data.
  • data-core is for tracked data files required as inputs by the workflows, such as site metadata and site mappings.
  • data-raw and data-proc must not be under version control.
  • Existing downloaded data must be moved rather than downloaded again.

Current Organization

Current data-raw directory

data-raw is already listed in .gitignore. It occupies approximately 9.2 GB and currently contains several different classes of files:

  • AmeriFlux BASE-BADM archives directly at the root, named like AMF_US-CMW_BASE-BADM_3-5.zip.
  • A root-level FLUXNET Shuttle snapshot and download log.
  • Source/site directories for AmeriFlux, ICOS, TERN, and isolated FLUXNET Shuttle archives.
  • Normalized ICOS and TERN CSV inputs under source/site paths.
  • Processed respiration files under RespirationData/, including paired _ac.csv and _nightNEE.csv files.
  • Predicted soil-temperature files under TS_RandomForest/.

The last two categories are workflow outputs, not raw download inputs, and should not remain in data-raw.

Proposed Organization

data-core/
  site_info.csv
  tern_fluxnet_site_mapping.csv

data-raw/
  Ameriflux/
    <site>/
      <downloaded AmeriFlux archive(s)>
  ICOS/
    <site>/
      <downloaded or normalized ICOS input(s)>
  TERN/
    <site>/
      <downloaded or normalized TERN input(s)>
  FLUXNET/
    <site>/
      <FLUXNET Shuttle archives and extracted files>

data-proc/
  soil-temperature/
    <site-specific workflow outputs>
  respiration/
    <source>/
      <site>/
        <site-specific respiration outputs>
  features/
    <source-specific growing-season tables>
  analysis/
    <cross-site priors, TAS, driver, simulation, and projection outputs>

data-core

Create a new tracked directory for stable prerequisites. Move site_info.csv and tern_fluxnet_site_mapping.csv there and update every workflow that reads them. These files are configuration-like scientific inputs, not generated results.

data-raw

Use source and site directories for downloaded inputs, with no processed outputs in this tree. The download scripts should default to these locations and should detect existing files at their new destinations before making a network request. Non-site download metadata such as the FLUXNET Shuttle snapshot can remain under a clearly named source-level metadata location if it is required to reproduce a download, but it is still raw input rather than a workflow product.

data-proc

Write every workflow output here, including per-site respiration files, predicted soil temperatures, growing-season feature tables, priors, model results, simulations, and future projections. Per-site outputs should retain source/site identity so files from different providers cannot collide.

Implemented Revision

  1. Extend .gitignore to ignore /data-raw/ and /data-proc/, while leaving data-core and data-proc-original trackable.
  2. Create data-core, move only the core metadata files into it, and remove those files from their old tracked locations.
  3. Create the new raw and processed directory trees.
  4. Move existing raw downloads into source/site directories without re-downloading them.
  5. Move existing workflow outputs into tracked data-proc-original and place future generated outputs under ignored data-proc.
  6. Update download scripts, workflow scripts, auxiliary scripts, demo paths, and documentation to use the new locations.
  7. Run static path searches and workflow-level validation without network downloads, then report any provider/site mapping ambiguities before resolving them.

Retained Classification

  • FLUXNET Shuttle archives and extracted files are retained only under data-raw/FLUXNET/<site>; current processing workflows do not read that tree.
  • Unmapped TERN files for Warra, Tumbarumba, AdelaideRiver, AliceSpringsMulga, and AlpinePeatland were removed; only the mapped FLUXNET-coded AU-Tum input remains.
  • The obsolete FLUXNET snapshot and fluxnet-shuttle-run.log were removed.
