ICOS Respiration Workflow

Implementation record for the ICOS-only Workflow 01 path.

Purpose

workflows/01_02c_filter_high_quality_night_respiration_ICOS.R prepares high-quality nighttime ICOS respiration observations without concatenating ICOS and FLUXNET files.

It consumes only normalized files written by workflows/93-download-icos.py under the ICOS L2 output directory.

Input And Output

The expected input name is {site}_ICOS_L2_FLUXNET_HH.csv.

The downloader-normalized columns used by the workflow are TIMESTAMP_START, TA_F_MDS, TS_F_MDS_1, TS_F_MDS_1_QC, NEE_VUT_REF, NEE_VUT_REF_QC, NIGHT, and optional SWC_F_MDS_1 and SW_IN_F_MDS.

The workflow writes data-raw/RespirationData/{site}_ac.csv and data-raw/RespirationData/{site}_nightNEE.csv.

Growing-season summaries are kept separate in data/growing_season_feature_ICOS.csv so that an ICOS-only result cannot silently overwrite the mixed-source EuroFlux result.

Processing

The workflow converts normalized timestamps to half-interval timestamps and derives calendar fields.

It filters for nonmissing air temperature, acceptable soil-temperature QC, measured NEE QC, ICOS nighttime flags, and NEE between -5 and 30.

It estimates growing-season bounds and temperature quantiles using the existing EuroFlux logic, removes years with large growing-season gaps, applies year_removed metadata, and writes the two established respiration schemas.

Unlike the existing EuroFlux workflow, it does not read FLUXNET files, join multiple source periods, or replace measured soil temperature with a random-forest prediction.

Downloader Change

The ICOS downloader now requests only columns needed for normalization from the Fluxnet and Meteo products.

For Meteosens it reads metadata first, selects the first available TS_* field, and requests only that field plus the timestamp.

This avoids failures caused by corrupted or unnecessary large response columns, and allowed the second-site download to complete.

Verification

The scripts parsed successfully with Rscript, and git diff --check reported no whitespace errors.

FR-FBn was downloaded or reused, then processed with:

Rscript workflows/01_01_estimate_soil_temperature_at_some_sites.R --sites=FR-FBn --overwrite
Rscript workflows/01_02c_filter_high_quality_night_respiration_ICOS.R --sites=FR-FBn --overwrite

FR-Fon was downloaded after the downloader column-selection change, then processed with the same two commands using FR-Fon.

Both site runs completed successfully and produced ICOS respiration outputs and feature rows.

The dominant difference is expected: the existing EuroFlux rows were generated from source configurations that combine historical FLUXNET and ICOS periods, while this workflow intentionally uses only the current normalized ICOS product.

The comparison therefore validates that the new path runs and produces the same feature schema, but it does not support treating the mixed-source and ICOS-only numerical results as interchangeable.

Five-Site Branch Test

The expanded ICOS test set was FR-FBn, FR-Fon, CH-Dav, FR-Bil, and DE-Tha.

All five normalized ICOS files were available and all five completed the ICOS-only respiration workflow.

01_01 completed for the four sites marked estimate_Ts=YES and produced their TS_RandomForest outputs.

DE-Tha was intentionally not accepted by 01_01, because the existing workflow only permits sites marked estimate_Ts=YES.

The test exercised the existing linear-regression branch for FR-FBn and the fallback branch for FR-Fon, CH-Dav, and FR-Bil.

The random-forest branches listed in 01_01 are not currently represented among ICOS-backed sites marked estimate_Ts=YES in data/site_info.csv; DE-Akm and CZ-RAJ are configured as FLUXNET-only there.
