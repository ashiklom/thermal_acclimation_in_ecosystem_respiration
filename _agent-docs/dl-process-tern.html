TERN Download and Processing Workflow

This document summarizes the TERN implementation completed for this project. TERN data are accessed through the Python terndata.flux package and translated into the FLUXNET-style CSV schema used by the downstream R workflows.

Implemented Files

  • workflows/94-download-tern.py: self-contained uv downloader and normalizer.
  • workflows/94-map-tern-sites.py: generates FLUXNET-to-TERN site mappings from coordinates.
  • workflows/01_02d_filter_high_quality_night_respiration_TERN.R: TERN-specific nighttime respiration processing.
  • workflows/01_01_estimate_soil_temperature_at_some_sites.R: recognizes normalized TERN inputs and preserves measured TERN soil temperature.
  • scripts/plot-growing-season-comparison.R: compares AU-Tum with two ICOS sites.
  • data/tern_fluxnet_site_mapping.csv: generated mapping for the current TERN-compatible site metadata.

TERN API

The implementation uses terndata.flux functions including get_sites, get_versions, get_variables, and get_subset.

The requested TERN variables are Fco2, Ta, Ts, Sws, Fsd, Fn, and ustar, together with their QC flags.

TERN timestamps represent the end of the half-hour interval. The normalizer therefore sets TIMESTAMP_START to the TERN timestamp minus 30 minutes and TIMESTAMP_END to the original timestamp.

Downloader and Normalization

workflows/94-download-tern.py is a standalone uv script with dependencies terndata.flux>=1.0.7 and pandas.

It accepts requested sites, a site-info file, a mapping file, data version, processing level, output directory, and an overwrite flag. The default processing level is L3.

When no sites are supplied, it selects AU-* records from data/site_info.csv. FLUXNET/site-info identifiers are resolved to native TERN identifiers using data/tern_fluxnet_site_mapping.csv. Downloads use the native TERN identifier, while output filenames retain the FLUXNET identifier.

For example, the current mapped output is:

data-raw/SiteData/TERN/unzip/AU-Tum_TERN_L3_FLUXNET_HH.csv

The normalized columns include:

  • NEE_VUT_REF and NEE_VUT_REF_QC from Fco2.
  • TA_F_MDS and TA_F_MDS_QC from Ta.
  • TS_F_MDS_1 and TS_F_MDS_1_QC from Ts.
  • SWC_F_MDS_1, SW_IN_F_MDS, NETRAD, and USTAR from Sws, Fsd, Fn, and ustar.
  • NIGHT, calculated as incoming shortwave radiation less than or equal to 20.
  • TIMESTAMP_START and TIMESTAMP_END in FLUXNET YYYYMMDDHHMM format.

Site Mapping

workflows/94-map-tern-sites.py queries the TERN site catalog and matches requested FLUXNET/site-info records to the nearest native TERN site by haversine distance.

The default maximum matching distance is 5 km. The generated mapping records the FLUXNET code, native TERN name, coordinates, distance, and whether the match is unambiguous.

The current verified mapping is AU-Tum -> Tumbarumba at zero coordinate distance.

TERN Respiration Processing

workflows/01_02d_filter_high_quality_night_respiration_TERN.R reads normalized TERN files and applies the source-specific nighttime filter:

  • Nonmissing air temperature.
  • Soil-temperature QC values 0, 1, or 2.
  • Measured NEE only, with NEE_VUT_REF_QC == 0.
  • NIGHT == 1.
  • NEE between -5 and 30.

It writes the standard downstream files:

data-raw/RespirationData/{site}_ac.csv
data-raw/RespirationData/{site}_nightNEE.csv

The ac output preserves the standard columns used downstream, including YEAR, MONTH, DAY, DOY, HOUR, MINUTE, NEE, TA, TS, SWC, NEE_uStar_f, daytime, SW_IN, and GPP_DT.

The TERN feature file is kept separate from the EuroFlux and ICOS feature files so that source-specific results do not silently overwrite one another.

Soil Temperature Workflow

01_01_estimate_soil_temperature_at_some_sites.R detects normalized TERN files and retains measured TS_F_MDS_1 as TS_pred in the expected TS_RandomForest output schema. This allows TERN files to enter the established soil-temperature workflow without requiring TERN-specific sensor-column metadata.

Testing and Generated Data

The TERN API site catalog and mapping generator were tested against live API responses. Native TERN downloads were checked for AdelaideRiver, AliceSpringsMulga, AlpinePeatland, Tumbarumba, and Warra. The canonical FLUXNET-mapped AU-Tum download was then verified separately.

For AU-Tum, both 01_01 and 01_02d were run with overwrite enabled. They produced data-raw/TS_RandomForest/AU-Tum_TS_rfp.csv, data-raw/RespirationData/AU-Tum_ac.csv, and data-raw/RespirationData/AU-Tum_nightNEE.csv.

Python syntax compilation, R parsing, and git diff --check passed. The source-specific TERN processing was exercised for AU-Tum; the earlier five-site check downloaded native TERN sites but did not create canonical FLUXNET-code outputs for all five.

AU-Tum Growing-Season Diagnostic

The resulting TERN row is:

site_ID,gStart,gEnd,tStart,tEnd,nyear
AU-Tum,3,364,3.03064654986343,16.3529839787171,23

The existing EuroFlux row is:

AU-Tum,185,380,3.08533333333333,16.3983365384615,12

The temperature limits are nearly identical, but the TERN algorithm identifies almost the entire calendar year as the growing season. Inspection of the downloaded TERN series showed that the daily NEE means remain below the algorithm's absolute -0.8 threshold throughout the year. Consequently, the seasonal candidate set contains essentially all days and the calculated bounds become 3 through 364.

This is a limitation of the copied absolute-threshold heuristic, not evidence that AU-Tum scientifically has a full-year growing season. The nighttime TERN NEE values have the expected positive respiration signal, so the problem is not a timestamp or NEE sign-conversion error. A future TERN revision should use a relative seasonal-amplitude criterion or a documented site-specific override.

Current downstream workflows read the EuroFlux and AmeriFlux feature files, not growing_season_feature_TERN.csv. They are therefore unaffected until explicitly changed to consume TERN features. If TERN features are added to a combined table, duplicate site_ID rows must be avoided or source selection must be explicit.

Visualization

scripts/plot-growing-season-comparison.R uses existing normalized files in data-raw/SiteData and compares AU-Tum with ICOS sites FR-FBn and FR-Fon. It displays NEE and soil temperature as separate rows and sites as columns.

Thin colored dashed lines show individual years. The thick black line shows the interannual daily climatology. Light gray background shading shows each site's source-specific identified growing season. Dotted reference lines show the NEE threshold and 0 degrees C soil temperature.
