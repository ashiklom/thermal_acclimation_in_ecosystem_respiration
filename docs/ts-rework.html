1. Why: what is wrong with the current soil-temperature path

The pipeline reconstructs soil temperature at a large fraction of its sites, and the reconstruction is almost always a function of air temperature:

GroupSitesWhat happens
ts_col = "TS_linear"35Measured TS overlaid with a TS ~ TA regression in step 02.
estimate_Ts = YES16fix_soil_temp() in step 01: random forest on TA + NETRAD (8), lm(TS ~ TA + NETRAD) (2), TS ~ TA otherwise.
SITES_TS_FROM_TA_*7AmeriFlux sites whose TS column is constructed from TA wholesale.
Manual year_removed20Hand-entered year exclusions.
Manual gStart/gEnd18 / 17Hand-entered growing-season overrides.

Out of 117 sites. Three problems follow.

Key risk A TS that is a function of TA may not support the direct/indirect decomposition

BRM_FORMULA_DIRECT separates a direct thermal response from indirect effects mediated by GPP and soil water. GPP is itself strongly driven by air temperature. Where TS is an affine function of TA, the variation that decomposition rests on has been collapsed by construction, and the estimate at those sites may not be the same quantity as at sites with real measurements.

This is testable now, cheaply, because prep_nee_ac() already carries TS_measured and TS_linear side by side and total_tas_site() takes a ts_col= override. Fit good-TS sites both ways and measure how far TAS moves. That result determines how much the rest of this work is worth, which is why it is first.

Key defect The random-forest skill estimate is measured on a split that cannot fail

predict_soil_temp() (R/predict-soil-temp.R:112-117) samples up to 60,000 half-hourly rows and splits them 70/30 at random. Half-hourly soil temperature is heavily autocorrelated, so a held-out row's neighbours are in the training set. The reported R² measures interpolation between adjacent half-hours, not the multi-year extrapolation the model is actually used for. The number is not wrong arithmetic; it is answering a different question from the one asked.

Generalisation None of the per-site decisions exist for a new site

Every branch above is keyed on a site name or a hand-filled site_info.csv column. A new site has none of them, so the pipeline cannot run at all. The fix is to make each decision the output of a screening function, demote site_info.csv to an override file, and validate the screener against the 117 existing manual calls — which are, conveniently, a labelled dataset that already exists.

Step 1 — does TS-from-TA change TAS? In progress

1a. TS_linear is now built at every site (R/prepare-site-data.R, R/soil-temp-columns.R). It was previously built only at the 35 sites that select it, which is precisely the set where no measured column survives to compare against. Building it everywhere changes nothing a normal run fits — ts_col still comes from site_info.csv, resolve_ts_column() still selects by name, and the assertion that TS leaves step 01 as the measured column still holds — but it makes the comparison possible at the 66 sites with genuinely measured soil temperature.

The one subtlety is the fitting domain. A site that declares TS_linear must declare ts_linear_domain too, and ts_fit_data() rejects a missing one; silently defaulting would let a half-filled row through and change that site's coefficients without a word. So ts_linear_domain_for() returns the declaration unchanged at declared sites and defaults to "ac" only where the column is a diagnostic. An un-fittable regression is fatal at a declared site and a logged skip anywhere else.

1b. The metrics are chosen for what the model does with the column, not for generic goodness of fit. total_tas_site() fits NEE ~ exp(alpha·TS + beta·TS²)·C0 inside each (14-day window × growing year) cell and then regresses the log-ratio of respiration against the cell-mean TS across years. The column therefore enters on two independent axes:

AxisStatisticWhat a distortion does
Within a cell, the spread of TS identifies alpha.within_sd_ratio — median over cells of sd(linear)/sd(measured).Inflate the spread and the fitted sensitivity deflates: the same NEE range is explained by a wider temperature range.
Across years within a window, the spread of cell means is the regressor TAS is the slope against.across_year_spread_ratio — median over windows of sd(linear)/sd(measured) of the cell means.Compress it and |TAS| inflates mechanically, whatever the respiration data say.

Alongside them, two physical diagnostics that say why the columns differ, and which are the same statistics step 3 will use for quality screening:

  • Diurnal amplitude ratio A(TS)/A(TA), median over growing-season days. Shallow soil damps the diurnal wave, so a measured sensor should sit well below 1. A regression on TA cannot damp anything: its amplitude ratio is the regression slope.
  • Diurnal phase lag, from the first harmonic of the hour-of-day climatology rather than which.max, which jumps by whole hours on a 24-point profile. Measured soil lags air by hours; a regression on TA lags it by exactly zero.

Both amplitudes are taken over a common set of sufficiently-complete days. Computed independently they are not comparable: TS_linear is non-missing wherever either TA or measured TS is, so it clears the completeness threshold on strictly more days than TA does, and the ratio then mixes the damping with which days each column happened to cover. On the first pass this alone moved US-Kon's apparent linear amplitude ratio from 0.86 to a figure inconsistent with its own regression slope; on a common day set it lands on the slope, as it must.

1c. A structural diff (scripts/ts-structural-diff.R) runs total_tas_site(fit = FALSE) under each column. That walks the real window and year loop with no sampling, so it reports exactly which windows the skip gate dropped, which years year_rejection() rejected and for which of its four reasons, and how many (window × year) cells would have been fitted. The substitution moves both the window means and the percentile bounds they are compared against, so the set of surviving cells can change before any model runs.

Step 2 — blocked cross-validation Done

Two questions, one harness (scripts/ts-fill-methods.R, scripts/ts-fill-cv.R). How optimistic is the random split, and which method should a site use? Each (method, blocking) pair produces one out-of-fold prediction per row, assembled into a complete series and scored by the same ts_reconstruction_metrics() used on TS_linear in step 1 — so the incumbent is one row of the same table, labelled in_sample, which is the honest description of a method the pipeline has no out-of-sample estimate of at all.

The methods add the one thing every existing one lacks. TS ~ TA and randomForest(TS ~ TA + NETRAD) are instantaneous maps, and shallow soil temperature is a damped, phase-lagged integral of the surface forcing — F2 measures exactly that damping and that lag. The *_memory methods add running means of air temperature over 3, 7 and 30 days plus day-of-year and hour harmonics, all from columns already present. Running means are taken on a daily series completed over the full date range rather than on half-hourly row offsets, because every record here has missing rows and a "30-day" mean over 1440 of them would span however many calendar days those rows happened to cover.

Blockings: random (the incumbent, kept so the comparison is a measurement), year, season and multiyear (two contiguous years). ranger stands in for randomForest — same algorithm, already a dependency, an order of magnitude faster, used on both sides of every comparison — so these numbers are not bit-identical to what the pipeline would produce.

Step 3 — a quality screen computed from the data alone Done

scripts/ts-qc-screen.R reads the raw spliced record, before prep_nee_ac() runs. That is the whole point: step 01 already applies the manual fixes — CZ-Stn's depth swap, FI-Sod's recalibration, GF-Guy's air-temperature substitution, fix_soil_temp()'s regressions — so screening its output would be marking its own homework. A new site has none of those fixes and the raw record is all it has.

The central diagnostic needs no metadata, which is what makes it work at a site the project has never seen. For a sinusoidal surface forcing, amplitude decays as exp(−z/d) and phase lags by z/d radians, where d is the damping depth. That is two independent estimates of the same dimensionless depth:

z/d from amplitude = -log(A_TS / A_TA)
z/d from lag       = lag_hours * 2*pi/24

A real buried sensor satisfies both and they agree. A sensor on the surface, pulled out, or reporting air temperature under another name has amplitude ratio near 1 and lag near 0. A dead or mislabelled-depth sensor has amplitude ratio near 0 with no matching lag. The ratio of the two estimates catches cases no single threshold does. Alongside it: stuck-value runs, spike rate against soil thermal inertia, coverage, the fraction genuinely measured rather than provider-gapfilled, mean TS−TA offset, and cross-depth coherence (amplitude must fall and lag must rise with depth, so columns ordered by name should be ordered the same way by amplitude — where they are not, the depths are mislabelled, which is the CZ-Stn / DE-Hte / FI-Sod class of problem).

One exemption is not optional: the stuck-value test ignores runs near 0 °C. A shallow sensor pinned at zero for weeks under snow is the zero curtain — latent heat of fusion buffering the soil at the freezing point — and is the most physically real signal in the record. Flagging it would condemn every seasonally snow-covered site in the network.

scripts/ts-qc-validate.R applies the verdict rules and compares them against the label formed from all five hand-flagging mechanisms the project uses. Measurement and rule-fitting are separate files so thresholds can be tuned without re-reading 23 GB. The label is noisy — ts_col = "TS_linear" was not applied on one consistent criterion — so the output lists disagreements in both directions for inspection rather than reporting an accuracy and stopping.

4. Findings

Measured over the 43 sites whose soil temperature is genuinely measured — neither reconstructed in step 01 nor substituted in step 02 — using scripts/ts-linear-vs-measured.R, scripts/ts-structural-diff.R and scripts/ts-bounds-definition.R.

F1 The substitution inflates the variation that identifies alpha, by a median factor of 1.73

The model fits NEE ~ exp(alpha·TS + beta·TS²)·C0 inside each (14-day window × growing year) cell. Within a cell, the spread of TS is what identifies alpha. Regressing soil temperature on air temperature replaces a damped signal with an undamped one, so that spread grows:

34 of 43 sites have their within-cell spread inflated by more than 25%. Inflating the predictor's spread while leaving the response alone deflates the fitted sensitivity: the same range of respiration is being explained by a wider range of temperature.

A correction to the first reading. On the single site inspected first (US-Kon) the across-year spread was compressed to 0.65, and the two axes looked like they were being pushed in opposite directions. Across 43 sites that does not hold: the across-year spread is close to unbiased on average (median 1.085). It is not harmless — 16 of 43 sites are off by more than 20% in one direction or the other — but it is site-specific noise in TAS rather than a systematic bias, whereas the alpha axis is systematically distorted in one direction at almost every site.

F2 The physical signature: the regression roughly doubles the diurnal amplitude and removes the phase lag

Shallow soil temperature is a damped, phase-lagged version of the surface forcing. That is what the heat equation says, and the measured columns show it:

The regressed amplitude ratio is the regression slope, necessarily — an affine function of air temperature cannot damp anything. So a reconstruction from air temperature does not approximate soil temperature badly; it produces a quantity with the wrong physical character, and F1 is the arithmetic consequence.

Selecting a column silently changes the definition of the gate as well as the data going through it.

Read them with the p-values, though. Only US-Whs has a TAS distinguishable from zero under either column, and there the substitution cuts the magnitude by 39% and degrades the p-value eightfold — at the one site in this sample where thermal acclimation is actually detected, reconstructing soil temperature from air temperature attenuates it substantially. The other four are not significant under either column, so a large relative change in an estimate that already straddles zero is less alarming than the percentages make it look. It still propagates: these point estimates are what the cross-site driver analysis consumes.

The mechanism predicted in F1 is confirmed, the magnitude is not predictable

Mean fitted alpha falls under the substituted column at 5 of 5 sites — 0.147→0.136, 0.108→0.086, 0.127→0.107, 0.121→0.101, 0.073→0.072 — which is exactly the direction F1 predicts from a within-cell spread inflated above 1. US-Whs, the one site whose within-cell ratio is below 1 (0.85), has by far the smallest change in alpha (−1.3%). So the alpha axis behaves as the arithmetic says it must.

TAS does not. The change in TAS has no usable relationship to the structural diagnostics across these five sites: US-Whs has the least distorted spread and the largest consequential change, US-Ro4 has one of the most distorted and essentially no change. I expected US-Whs to be a null control on the grounds that its measured sensor is already air-like, and that was wrong. The practical consequence is that the cheap diagnostics cannot be used to certify that the substitution is harmless at a given site — which removes the most attractive shortcut and is an argument for replacing the reconstruction rather than triaging it. Five sites is a small basis for a negative claim, and it is the claim this result supports least strongly.

The improvement is not only in RMSE, which is the point of scoring on the model's own axes. The incumbent over-disperses within a cell by 74% and inflates diurnal amplitude 2.0× with no lag at all; rf_memory lands at 0.90 and 0.83 and recovers a 1.45 h lag against a measured median of 1.73 h. Cell-mean RMSE — the error in the quantity the TAS regression actually reads — falls from 1.81 to 0.82 °C.

The random forest on instantaneous air temperature is the worst method tested, worse than the plain linear model it exists to improve on, and inflates diurnal amplitude 2.9×. It is one of the two branches fix_soil_temp() uses in production.

Net radiation adds almost nothing once memory is present. rf_memory_netrad is marginally worse than rf_memory in the median (on a 30-site subset, so not strictly comparable), though it is the per-site winner more often. Memory dominates radiation.

What is still wrong with the best method. Within-cell ratio 0.90 and across-year ratio 0.87 are both slightly below 1: the reconstruction is a little too smooth. That is regression to the conditional mean, and it biases alpha in the opposite direction to the incumbent. Much smaller, but it is the argument for drawing from the predictive distribution rather than plugging in its mean — step 5.

I overstated this defect when I first described it. With only instantaneous air temperature as a feature there is nothing to memorise: two rows with the same TA are indistinguishable to the model, so a random split of autocorrelated half-hourly rows costs almost nothing. predict_soil_temp()'s reported skill is therefore not badly optimistic for the features it uses.

The optimism appears the moment memory features enter — which is exactly the improvement worth making. Keep the random split and adopt rf_memory, and you would measure RMSE 0.78 and believe it, when the honest figure is 1.26. So fixing the cross-validation is a prerequisite for adopting a better method rather than a correction to the existing one. year and multiyear blocking agree closely (1.26 vs 1.28 for rf_memory), so skill degrades little when the gap being filled grows from one year to two.

One implementation note: the incumbent's in-sample RMSE (3.03) and its blocked out-of-fold RMSE (3.04) agree to two decimal places, which is both the expected behaviour of a two-parameter model and a check that this harness reproduces what the pipeline does.

The right conclusion is not "the humans were wrong" but that ts_col = "TS_linear" is not a soil-temperature quality label, and treating it as one — which is what the column name invites — is unsafe. These nine sites are the list to put to the authors.

F11 The data falsified two of my three structural rules

Kept here because the corrections are the useful part, and both are in the source.

Phase is only known modulo 24 hours. A strongly damped sensor lags by more than half a day and the harmonic phase wraps. DE-Hte's measured −7.8 h is +16.2 h; reading it as "soil leads air" is simply wrong. The amplitude supplies the prior that picks the branch, so the two diagnostics have to be resolved jointly rather than compared independently.

The two estimates of z/d do not agree, and should not. I claimed a real buried sensor satisfies both and they agree. Over the network the ratio has median 2.45, interquartile range 1.70–3.43 — nowhere near 1. The reason is that the clean theory forces the soil surface, and air temperature has a canopy and a surface boundary layer in front of it, which attenuate diurnal amplitude a great deal while adding little phase lag. So the amplitude ratio carries canopy attenuation plus soil damping while the lag carries soil damping alone. The check survives as a relative test against the network's own central range — which is the better form for it anyway, since that is what a new site can be judged against, and it suggests conditioning on IGBP class, because canopy density is what drives the discrepancy.

Column name order is not depth order in AmeriFlux. TS_F_MDS_1/2/3 increase in depth, but TS_<h>_<v>_<r> puts the vertical index second, so TS_1_1_1 and TS_2_1_1 are two horizontal positions at one depth. Sorting by name fired the rule at 55 of 94 sites; parsing the vertical index brings it to 2, both hand-flagged.

F6 Pre-existing: US-ICs cannot be processed at all

prep_ameriflux() fills soil-temperature gaps at US-NR1, US-ICh and US-ICs from a column named TS_PI_1 (R/ameriflux.R:244). That column is not in US-ICs's current AmeriFlux BASE download, so a$TS_PI_1 is NULL and the assignment dies with replacement has length zero. Untouched by anything on this branch — it is a hard-coded column name that stopped matching when the provider's file changed, which is the failure mode the whole rework is aimed at.

F7 Coverage limits on all of the above

Of 58 sites with genuinely measured soil temperature, 43 produced results. Twelve fail because their declared FLUXNET/ICOS products are not in data-raw/ (they were not in refactor/ either, so this is not a copying artefact), one is US-ICs per F6, one is BR-Ma2, and one — BR-Sa1 — stops at southern hemisphere sites not implemented yet. No downloads have been triggered; say the word and the twelve can be fetched, which would take the sample to 55.

Fixed F0. The conda-forge r-base64url osx-arm64 build is broken, and targets cannot load without it

A clean pixi install on this machine produces an unusable environment: library(targets) fails with shared object 'base64url.so' not found. The cause is upstream, not local. The artifact r-base64url-1.4-r45hbe92478_1008.conda contains 25 paths that are the package source tree — src/, vignettes/, conda_build.sh, build_env_setup.sh — with no Meta/package.rds and no compiled .so. Clearing the rattler cache and re-downloading reproduces it byte for byte, and it is the only osx-arm64 build conda-forge offers for 1.4, so no version constraint avoids it.

The package does not even appear in installed.packages(), which is why the failure surfaces as a missing shared object rather than a missing package.

Fix: added base64url to the CRAN list in dependencies.R, which is the project's existing mechanism for real packages pixi cannot supply (it already carries REddyProc, gslnls, lutz, amerifluxr). pixi run deps now compiles the real package over the top and targets loads.

Worth knowing: the refactor/ environment has a correct base64url despite recording the same broken build hash in conda-meta. That environment was repaired by hand at some point and the repair was never written down, so refactor/ was not reproducible from a clean checkout. It is now.
